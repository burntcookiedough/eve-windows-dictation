# CPU first-run model decision

This follow-up uses the same packaged Windows CPU candidate and WebSocket stop-to-final-text harness as [the original benchmark](eve-cpu-dictation-benchmark.md). It answers which model a **new** CPU-only Eve profile should select. Existing profiles retain their saved choice or the historical `large-v3-turbo` default. Model files are downloaded separately from the installer.

## Representative speech check

Ten different-speaker, 6.05–8.43-second excerpts from the [LibriSpeech `dev-other` corpus](https://www.openslr.org/12/) were converted to mono 16 kHz PCM. Each configuration received the same files, one warm-up, and two measured dictations per clip. The corpus archive's MD5 was `c8d0bcc9cca99d4f8b62fcc847357931`; the task-local manifest records each source utterance, transcript, and WAV SHA-256. The harness streamed audio at real-time pace through Eve's packaged Python server, then measured the stop command to the final WebSocket text frame. These are read audiobook samples, not physical-microphone dictation or paste into another app. Raw word error counts spelling and number-format differences as errors; it is a comparative signal, not an estimate of everyday accuracy.

| Configuration | Model | Native compute | Audio | Stop to text median | p95 | Median RTF | Peak server RSS | Raw pooled WER |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| CPU, Eve thread default | `small` | `int8_float32` | 20 × 6–8 s | 3.15 s | 4.39 s | 0.47 | 625 MiB | 46/384 = 12.0% |
| CPU, eight OpenMP threads | `small` | `int8_float32` | 20 × 6–8 s | 3.93 s | 5.15 s | 0.61 | 628 MiB | 46/384 = 12.0% |
| CPU, eight OpenMP threads | `base.en` | `int8_float32` | 20 × 6–8 s | 1.04 s | 1.38 s | 0.16 | 373 MiB | 58/384 = 15.1% |
| Optional NVIDIA pack | `large-v3-turbo` | `int8_float16` | 20 × 6–8 s | 0.81 s | 1.02 s | 0.12 | 754 MiB | 26/384 = 6.8% |

The measured p95 is the nineteenth ordered value out of twenty. CPU percentage during the **final** interval averaged about 396% of one logical core for default-thread `small`, 787% for eight-thread `small`, 788% for eight-thread `base.en`, and 98% for GPU turbo on this 16-logical-processor host. This is process CPU use, not whole-machine CPU percentage. The packaged server reached model-ready HTTP health in 3.21 seconds for default-thread `small`, 3.56 seconds for eight-thread `small`, 3.09 seconds for `base.en`, and 7.20 seconds for GPU turbo with cached weights. Initial downloads and Electron launch are excluded from these four startup observations. The word-error scorer did not equate spoken number words with digits, so one numbers-heavy clip overstates the quality difference between `small` and GPU turbo.

The eight-thread `small` run was slower than the untouched thread default on this corpus, so this change does **not** tune OpenMP threads. `base.en` is much faster but English-only and made more meaningful substitutions on some excerpts; it is not a safe universal first-run choice. `small` retains the multilingual model path and substantially improves short CPU dictation over the historical CPU turbo result (22.25 seconds for a 2.10-second synthetic utterance and 16.14 seconds for an 8.84-second one). Even so, a 3.15-second median after ordinary 6–8-second speech is a noticeable delay. The GPU pack remains the clearly more responsive, more accurate tested choice on this corpus, while costing about 495 MB compressed and 771 MB installed separately from the CPU app.

## Runtime decision and boundaries

For a genuinely empty packaged Windows Eve profile, bootstrap writes `{"whisper_model":"small"}` before the app starts. It checks freshness immediately after the profile path is created and validated, before Electron adds cache files, then writes only after the single-instance lock. Existing profiles remain untouched even when their old turbo default was never written to settings. An explicit `MURMUR_WHISPER_MODEL` environment override also prevents seeding. The server retains a saved model choice when an unrelated settings update occurs under a temporary environment override. A fresh profile uses `small` even if a GPU pack is already installed; choosing turbo for GPU use remains an explicit model choice.

This is a CPU usability improvement, not a claim that CPU Eve now feels instant. The original measurement found that inference and contention with partial transcription dominate final latency; Electron's text display adds only tens of milliseconds in the instrumented overlay trials. Disabling partials on `small` saved roughly 0.2 seconds in short scripted samples and would disturb speech-based auto-stop, so partial transcription remains enabled. No PyTorch, model weights, or extra inference dependency is added to the installer. The optional GPU pack, saved CUDA preference, and CPU fallback remain independently supported.

The rebuilt package measured 178,040,192 bytes for the NSIS web payload and 685,812,939 bytes fresh unpacked: 830 and 6,642 bytes above the source-matched PR 87 package respectively. In isolated packaged-app launches, an empty profile gained `whisper_model=small`, while a profile with an existing history database did not gain a model setting. These checks used offline model access and did not exercise an initial model download.

The final packaged Python runtime also transcribed a short clip on CPU and, separately, on CUDA using the installed optional pack. Its health report and runtime fingerprint identified CPU without an active GPU pack in the first run, and CUDA with the expected pack ID in the second. Windows module enumeration returned `WinError 234` for this deeply nested checkout, so those final smokes do not independently prove DLL origins. The earlier, shorter-path PR 87 package did verify loaded DLL origins; this change does not modify the GPU loader or bundled native libraries. These two single-run smokes are functional validation, not additions to the latency sample above.

The task-local JSONL records live outside the repository under `cpu-benchmark/human-eval-librispeech-dev-other`. This follow-up does not establish physical-microphone accuracy, paste latency, multi-hour thermal behavior, a clean-machine GPU download, or the accuracy of untested model candidates.

## Model adapter scope

Eve already has one server-owned Faster-Whisper/CTranslate2 catalog and an adapter that accepts explicit Hugging Face repository IDs or local model paths. A second adapter would add code and dependency risk without providing another inference capability. The measured `base.en` result supports a possible optional **Fast English** choice, but its English-only constraint, worse transcript score, and independent language setting need a deliberate UI rule before it enters the curated catalog. It is not included in this change.

Two source-backed, **unmeasured in Eve** experiments are [Distil-Whisper medium.en](https://huggingface.co/Systran/faster-distil-whisper-medium.en) (about 792 MB of preconverted weights) and [Distil-Whisper large-v3](https://huggingface.co/Systran/faster-distil-whisper-large-v3) (about 1.52 GB). Both fit the existing CT2 adapter and are English-only. The next experiment should try medium.en first against the same packaged stop-to-text protocol and human clips, then extend the corpus with actual dictation, names, dates, and amounts. Upstream model claims are not Eve performance results. The existing multilingual `medium` model is already in the catalog and is roughly turbo-sized, so it is less promising as a CPU responsiveness fix.
