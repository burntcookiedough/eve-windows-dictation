Context

Why explore a new engine?

Murmur's current architecture works, but faster-whisper has inherent limitations for real-time desktop transcription.

⏱

Latency Gap

Whisper processes audio in ~1 second chunks. Users experience a noticeable delay between speaking and seeing text appear.

⚡

Simulated Streaming

faster-whisper uses buffered pseudo-streaming—batch inference on accumulated audio, not true token-by-token output.

🔬

VRAM Overhead

large-v3-turbo needs 4–6 GB VRAM. On consumer GPUs shared with other apps, this creates memory pressure.

💡

The goal: evaluate NVIDIA Nemotron Speech as a drop-in upgrade—faster latency, native streaming, lower resource usage, while preserving Murmur's user experience.

# engine interface (simplified) class TranscriptionEngine(ABC): async def start(self, config): """Initialize the engine""" ... async def transcribe_chunk(self, audio): """Process an audio chunk""" ... async def stop(self): """Clean up resources""" ... # Usage in server engine = get_engine("nemotron") # or "whisper" await engine.start(config)

Why this approach?

  • Single server binary — no additional install complexity
  • Hot-swappable — switch engines via settings, no restart needed
  • Frontend unchanged — same WebSocket protocol, same IPC
  • Testable — each engine is independently unit-testable
Roadmap

Migration path

A phased approach that keeps Murmur stable while we integrate Nemotron.

Phase 1 — Research Now
Benchmark Nemotron models, validate accuracy on English transcription use cases, document integration requirements.
Phase 2 — Engine Interface
Define TranscriptionEngine ABC. Refactor current Whisper code to implement it. Add engine selection to settings.
Phase 3 — Nemotron Integration
Implement NemotronEngine class. Set up NeMo/ONNX pipeline. Wire up native streaming to WebSocket protocol.
Phase 4 — UI & Polish
Add engine selector to main window settings. Show engine badge on overlay. Streaming text animation for Nemotron's real-time output.
Phase 5 — Ship
Default to Nemotron for English users. Keep Whisper as fallback for multi-language and as a legacy option. Auto-detect GPU capabilities.

Risk mitigation

  • No breaking changes
    WebSocket protocol stays identical. Frontend doesn't know which engine is running.
  • Whisper always available
    Whisper remains as fallback. Users can switch back at any time.
  • GPU auto-detection
    If no NVIDIA GPU or insufficient VRAM, default to Whisper CPU mode.
